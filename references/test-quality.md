# Competitive programming test-quality rubric

Use this rubric as a checklist, not as a substitute for problem-specific reasoning.

## Mandatory test classes

1. **Official sample parity:** every published sample matches source input/output exactly.
2. **Small exhaustive:** enumerate all valid small instances where feasible; compare brute vs reference.
3. **Constraints:** min/max for each field, strict and weak boundaries, sum-of-sizes, number of test cases, zero where allowed, maximum permitted result.
4. **Shape:** uniform, repeated, all distinct, monotone, alternating, sparse/dense, connected/disconnected, skewed/balanced, deep/shallow; only when applicable and valid.
5. **Numeric:** `int32` and `int64` overflow exposures, negative values, large products and sums, modulo zero residue, precision traps; only when permitted by constraints.
6. **Algorithmic adversaries:** greedy counterexamples, incorrect binary search monotonicity, off-by-one indices, equality handling, shortest-path tie cases, DP state order, graph back-edges, recurrence cycles, hashing collisions, queue/state explosions; select only relevant classes.
7. **Scale:** near-max input bytes, runtime-stress, memory-stress, multi-case aggregate max.
8. **Reproducibility:** fixed seeds, generator version/hash, manifest mapping test IDs to intended bug patterns.

## Required gates

- Validator accepts every generated input and rejects a negative set of deliberately invalid inputs.
- Each output is generated by running the compiled reference; no manually guessed answer.
- Official samples are byte/semantic-equivalent as the official checker requires.
- Independent brute/alternative agrees on all comparable tests.
- Target limits are measured or discrepancies explicitly declared.
- At least one known-wrong implementation is tested for each principal failure class when available.
- Every failure case is saved with seed and minimized reproduction when practical.
- For each original subtask, provide representative cases and full-range stress; do not claim original point distribution is preserved without the published subtask grouping and weights.
